# 여기야 프런트엔드

Expo SDK 57 · React Native · TypeScript. 추가 UI/지도 서비스 의존성 없이 웹·iOS·Android 공용 화면을 구성합니다.

## 주요 파일

- `src/features/journey/home-screen.tsx`: 역 검색과 `길찾기 / 내 여정 / 알림` 하단 메뉴.
- `src/features/journey/route-result-screen.tsx`: 구간 시간 비율 막대, 차량 선택, 선택 차량별 하차 알림 설정.
- `src/features/journey/vehicle-track.tsx`, `src/features/transit/vehicle-motion.ts`: 고정된 역 사이의 차량 표시와 화면용 예상 이동. 실시간 관측과 알림 계산은 분리합니다.
- `assets/vehicles/`: 지하철·버스 측면 에셋. 차체와 색상 띠를 분리해 노선 색상을 적용합니다.
- `src/features/journey/route-service.ts`: 기존 지하철 연결망과 비용 공급자를 공통 평균 그래프 엔진에 연결하는 어댑터.
- `src/features/transit/journey-plan.ts`: 경로를 승차·환승·도보 구간으로 분리하고 선택 차량을 구간에 연결.
- `src/features/transit/average-route-engine.ts`: 지하철·버스 공통 Node/Edge의 평균시간 탐색. 대기시간은 알 수 없음으로 유지.
- `src/features/transit/timetable-engine.ts`: 실제 Trip/StopTime을 공급받았을 때의 출발시각별 최초 도착 탐색.
- `src/features/transit/gunpo-routing.ts`, `src/services/gunpo-bus.ts`: 군포 실시간 버스 도착정보와 거리 기반 시간을 이용한 도보·버스·미래 시각 지하철 연결.
- `src/features/journey/bus-track.tsx`: 노선 정류장 순번과 일치하는 실제 버스 선택. 같은 정류장을 다시 지나는 경우도 구분합니다.
- `src/features/transit/timetable-plan.ts`: 시간표 탐색 결과를 버스·지하철·대기·환승·도보 JourneyPlan으로 변환. RouteResultScreen의 `plan` 입력으로 표시할 수 있습니다.
- `src/services/subway-vehicle-candidates.ts`, `src/services/bus-vehicles.ts`: 실시간 위치·도착 정보에서 선택 가능한 차량 후보 구성.
- `src/services/current-location.ts`, `src/features/stations/nearby-stations.ts`: 전경 GPS 1회 조회와 기기 내 가까운 역 검색. 좌표는 경로 그래프와 분리합니다.
- `src/features/stations/network.ts`: 노선 색상, 역 순서, 지선, 단방향 연결, 역명 별칭.
- `src/features/notifications/`: 플랫폼별 알림, 카운트다운, 화면 전체 하차 안내창.

## 로컬 노선망 범위

이 목록 밖의 수도권 노선은 검색되지 않습니다. 검색·선택에서는 환승역 하나에 여러 호선을 표시합니다.

| 노선 | 지원 구간 |
| --- | --- |
| 1 | 연천–신창, 구로–인천, 금천구청–광명, 병점–서동탄 |
| 2 | 순환 본선, 성수–신설동, 신도림–까치산 |
| 3 | 대화–오금 |
| 4 | 진접–오이도 |
| 5 | 방화–하남검단산, 강동–마천 |
| 6 | 응암 순환(단방향), 응암–신내 |
| 7 | 장암–석남 |
| 8 | 별내–모란 |
| 9 | 개화–중앙보훈병원, 일반열차만 |
| 신분당 | 신사–광교 |

역 ID는 앱 내부 식별자이며 공식 API 역 코드가 아닙니다. 기존 `mock-`/`seoul-` 호선별 저장 ID는 통합 역 ID로 복원합니다.
`총신대입구(이수)`/`이수`는 `이수(총신대입구)` 하나로, 금정은 1·4호선을 가진 하나의 역으로 표시합니다.
`당고개`/`뚝섬유원지` 검색도 새 역명으로 연결합니다. 상세 기준과 참고 자료는 [역 데이터 안내](../docs/station-data.md)에 기록합니다.
공식 경로 조회를 우선하고 거리·정차·환승 대기를 반영합니다. 설정과 제한은 [공식 경로 연동](../docs/official-routes.md)을 참고하세요. 아래 시간 규칙은 API 실패 시 임시 예상값에만 적용합니다.
2호선 지선은 성수·신도림에서 환승 5분을 적용하되 해당 역 자체에서 출발·도착할 때는 제외합니다.
5호선 분기 간 이동처럼 열차 방면을 바꿔야 하는 경우 실제 대기 시간은 계산하지 않습니다.
노선망은 수작업으로 관리하는 프로토타입 데이터이며 운영기관의 실시간 노선 변경을 자동 반영하지 않습니다.

## 차량 선택과 알림

- 지하철은 실시간 도착·위치, 버스는 TAGO 차량 위치가 있는 구간에서만 실제 후보를 표시합니다. 번호가 같아도 추천 시간표의 Trip과 동일 운행인지 단정하지 않습니다.
- 버스·지하철의 색상은 경로 막대와 차량 위치에 적용하며 메인 초록색은 유지합니다. 도보·환승은 별도 중립색입니다.
- 지하철 후보는 경로의 정차 순서·상하행/내외선·종착역을 비교해 고릅니다. 반대 방향·중간 종착·다른 지선·정차망 미확인 급행을 제외합니다. 이 판정은 추천 시간표의 Trip 일치 판정과 별개입니다.
- 실제 차량 정보는 30초마다 조회하며 진행 방향의 시작역부터 하차역까지 한 줄로 표시합니다. 승차역 이전 열차도 노선에 포함하고 하차역 뒤의 역·별도 화면 밖 차량 목록은 표시하지 않습니다. 겹치는 차량은 대수 배지를 눌러 개별 차량을 고릅니다.
- 출발은 출발역 다음, 운행 중은 역 사이, 진입은 다음 역 바로 앞에 표시합니다. 도착이 확인될 때만 역 점 위에 놓습니다. 같은 구간의 갱신은 진행도를 유지합니다.
- 다음 역의 동일 호선·번호·방향 차량 도착 예정 시간이 있으면 예상 진행도를 계산합니다. 필요한 역만 중복 없이 최대 7개 조회합니다. ETA가 없으면 첫 관측 상태와 평균 구간 시간으로 보간하며 API 수신 시각을 실제 출발 시각으로 쓰지 않습니다. 예상 진행도가 94%여도 실제 도착으로 처리하지 않습니다.
- 정보가 오래됐거나 조회에 실패하면 움직임을 멈춥니다. 화면의 예상 위치는 승차 가능 여부와 알림 계산에 사용하지 않습니다. 승차·알림은 관측된 운행 구간과 도착 정보로 판단하며 버스는 제공된 관측 위치만 표시합니다.
- 시간 기반 단일 알림. 선택한 차량의 위치/도착 정보와 구간 예상시간으로 도착 1·2·3개 역 또는 정류장 전 예상 시점을 계산합니다. 이후 지연에 맞춰 자동 재계산하지 않습니다.
- 중복 예약 방지, 카운트다운, 취소, 종료, 웹 새로고침 후 예약 복원.
- 만료되면 현재 탭/화면에 관계없이 하차 안내창을 표시합니다.
- 웹의 화면 내 알림은 권한 없이 시작합니다. 브라우저 알림은 별도의 허용 버튼을 사용합니다.

`군포 버스도 함께 찾기`를 켜고 출발지로 `내 위치`를 사용하면 군포 30·31번의 버스 1회 → 금정·산본역 → 지하철 경로를 비교합니다. 출발역을 군포·당정·금정·산본·수리산·대야미로 직접 고른 경우도 해당 역 좌표에서 비교합니다. 지하철역으로 바로 걸어가는 편이 빠르면 버스 없는 경로가 나올 수 있습니다. 노선별 상세 범위와 계산 기준은 [군포 버스 시범 연결](../docs/gunpo-bus-pilot.md)을 참고하세요.

출발지·도착지에서 `내 위치`를 누르면 위치 권한을 요청하고 현재 좌표를 한 번 읽습니다. 앱에 포함된 역 좌표와 비교해 3km 안의 가까운 역을 연결하며, `역 변경`에서 최대 3개 후보 중 다른 역을 고를 수 있습니다. 출발·도착을 바꾸면 GPS 위치와 연결 역도 함께 이동합니다. 직접 입력하거나 지우면 해당 위치 선택이 해제됩니다.

역 좌표는 서울특별시의 [서울시 역사마스터 정보](https://data.seoul.go.kr/dataList/OA-21232/S/1/datasetView.do)를 앱의 지원 역 ID와 연결한 데이터입니다. 출처, 지원 범위와 갱신 방법은 [역 좌표 안내](../docs/station-locations.md)를 참고하세요.

거리 표시는 역 좌표까지의 직선 거리입니다. GPS 출발 검색은 가까운 역까지 도보·승강장 진입 추정시간을 포함하고, 군포 버스를 이용하면 정류장까지 도보·실시간 승차 대기·버스 이동·역 환승을 이어 계산합니다. 도보 경로·출입구 안내는 제공하지 않습니다. GPS 목적지는 선택한 연결 역에서 마지막 도보 추정시간을 더합니다. 위치 좌표는 메모리에만 보관하고 외부 서버로 전송하거나 백그라운드에서 추적하지 않습니다. API에는 역 이름과 공개 노선·정류장 ID, 검색 시각만 전달합니다.

iPhone의 Expo Go에서 `내 위치`를 누른 뒤 위치 접근을 허용하세요. 권한을 차단한 경우 버튼 아래의 설정 이동을 이용할 수 있습니다. 웹 위치는 HTTPS 또는 localhost에서 지원되며, LAN의 일반 HTTP 주소에서는 Expo Go를 사용하세요. 권한·위치 서비스·오래된 좌표·조회 시간 초과를 각각 처리합니다.

시간표 데이터의 내부 `routeId`와 `StopTime.sequence`는 실시간 API의 노선 ID·노선 정류장 순번과 별개입니다. `TimetablePlanCatalog`의 `providerRouteId`와 `tripStopSequences`로 명시적으로 연결해야 합니다. 매핑이 없으면 실시간 조회용 ID·순번을 비워 두며, 부분 운행이나 순환 노선의 Trip 순번을 제공자 순번으로 추정하지 않습니다.

## 수동 확인

1. 강남 → 시청 검색 후 막대 너비가 구간 시간 비율을 반영하고 2·4·1호선 색이 서로 다른지 확인.
2. 지하철 구간을 열어 시작역부터 하차역까지의 실시간 열차를 고르고 `탈 예정`·`지금 타고 있어요` 가능 여부를 확인.
3. 도착 예정 시간이 있는 열차를 선택하면 알림 기준역과 예상 시각이 아래에 나타나는지 확인.
4. 하단 `알림` 탭으로 이동했다가 돌아와도 선택 열차가 유지되는지 확인.
5. 중계 서버를 중지하면 실시간 차량 조회 오류가 표시되되 임시 경로 결과는 유지되는지 확인.
6. 너비 390px와 1440px에서 입력, 가로 정차역 스크롤, 하단 메뉴와 알림창 확인.
7. 실기기: 알림 권한 허용/거부, 소리, 백그라운드, 앱 재시작, 예약 취소 확인.
8. iPhone에서 출발·도착 입력 시 하단 메뉴가 숨겨지고 입력창이 위로 정렬되는지, 후보 목록을 키보드 위에서 스크롤·선택할 수 있는지 확인. 입력 중 페이지 정렬은 최초 포커스 시 한 번만 수행합니다.
9. 열차의 역 진입·도착·출발 상태, 30초 위치 갱신 사이의 예상 이동, 차량 선택 유지, 정보 지연 시 정지와 동작 줄이기 설정을 확인.
10. 금정 → 산본은 하행, 금정 → 이수는 상행 열차만 표시되는지 확인. 산본 진입 열차는 금정–산본 구간 끝부분에 있고, 새로고침해도 도착 확인 전에는 산본 역 점으로 옮겨지지 않아야 합니다.
11. 금정 → 어린이대공원 여정에서 4호선은 오이도 → 이수, 7호선은 석남 → 어린이대공원으로 표시되는지, 승차역이 처음 가운데 보이고 이전 역들을 가로로 스크롤할 수 있는지 확인.
12. iPhone에서 출발지와 도착지 각각 `내 위치` 선택, 가까운 역 변경, 출발·도착 바꾸기, 직접 검색 복귀를 확인. 권한 거부/설정 이동, 위치 서비스 꺼짐, GPS 조회 중 입력 변경 시 늦은 결과가 기존 입력을 덮어쓰지 않는지 확인.
13. 군포 30·31번 정류장 주변에서 GPS 출발 검색. 도착 전에 지나갈 버스를 제외하고 도보·대기·버스·금정/산본 환승·지하철 시간이 막대에 표시되는지 확인. 해당 위치에 버스가 유리하지 않거나 도착정보가 없으면 직접 역 도보 경로가 나올 수 있습니다.
14. 버스 구간을 열어 실제 차량을 선택. `탈 예정` 또는 `지금 타고 있어요` 선택 뒤 미래 시각 지하철 연결이 갱신되는지, 탑승 중 재선택과 빠른 연속 선택에도 구간이 유지되는지 확인.
