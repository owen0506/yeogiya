# 단계별 개발 계획

| 단계 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 기본 화면 + 폴더 구조 | 구현 완료 |
| 2 | 역 검색 더미 데이터 | 구현 완료 |
| 3 | 경로 결과 화면 | 데모 부분 노선망 기반 구현 |
| 4 | 서울시 실시간 API 호출 service 파일 | 구현, 인증키를 이용한 실호출 검증 필요 |
| 5 | 알림 로직 | 예상 시간 기반 예약/취소 구현, 실기기 검증 필요 |

## 프런트엔드 구조

- `src/app/`: Expo Router 진입점 및 라우트
- `src/features/journey/`: 이동 입력 화면. 3차에서 경로 결과 화면 추가
- `src/features/stations/`: 2차 역 데이터와 검색 기능
- `src/features/notifications/`: 5차 하차 알림 기능
- `src/services/`: 4차 외부 API 통신
- `src/constants/`, `src/components/`, `src/hooks/`: 기존 공통 상수, 컴포넌트와 훅

1차 화면은 출발·도착역 자유 입력, 입력값 교환, 1개/2개 역 전 알림 시점 선택을 제공합니다.
2차에서는 더미 데이터 기반 역 부분 검색과 노선별 선택, 선택 해제, 동일 역 안내를 제공합니다.
입력값은 앱 재시작 시 유지되지 않습니다. 두 역을 선택하면 경로 검색 버튼이 활성화됩니다.
기존 Expo 예제 파일은 보존하되 홈 화면에서는 사용하지 않습니다.

## 실행 및 확인

`frontend`에서 `npm start` 또는 `npm run web`으로 실행합니다.
타입 검사는 `npx tsc --noEmit`으로 실행합니다.

수동 확인: 역 이름 입력, 교환 버튼, 알림 시점 선택, 작은 화면 스크롤과 키보드 표시를 확인합니다.

## 3~5차 구현 및 체험

1. 홈에서 강남 2호선 → 잠실 2호선을 선택하고 경로 검색을 누릅니다.
2. 6개 역 이동·환승 0회·데모 예상 시간 12분과 경유역을 확인합니다.
3. `10초 체험 알림`을 누르고 권한을 허용하거나, 웹에서는 화면 내 알림을 확인합니다.
4. 홈으로 돌아가도 예약 상태가 표시됩니다. `알림 취소` 또는 `알림 확인 · 종료`로 끝냅니다.
5. `탑승 완료 · 예상 시간 알림 시작`은 선택한 1개/2개 역 전 시점을 경로에서 역산합니다.

경로는 부분 노선망 안에서 시간 가중치로 탐색합니다. 모든 수도권 노선/급행/시간표를 지원하지 않습니다.
중간역을 경로에 포함하지만 검색 목록은 2차의 25개 노선별 항목을 유지합니다.
실제 최단 경로 안내가 아니며 역간 2분, 환승 5분이라는 데모 가정을 사용합니다.
실시간 API 정보는 참고용입니다. 탑승 열차 자동 추적·실시간 위치 기반 재예약은 아직 지원하지 않습니다.

## 실시간 API 설정

Node.js 22.13 이상에서 실행합니다. Spring Boot 도입 전 사용할 개발용 Node 중계 서버를 제공합니다.

1. `backend/.env.example`을 `backend/.env`로 복사하고 `SEOUL_SUBWAY_API_KEY`에 서울시 지하철 실시간 API 인증키를 입력합니다.
2. `backend`에서 `node --env-file=.env seoul-proxy.mjs`를 실행합니다.
3. `frontend/.env.example`을 `frontend/.env`로 복사합니다.
4. Expo 서버를 재시작합니다. `npm run web`으로 열고 경로 결과에서 실시간 정보를 조회합니다.

인증키 없이 중계 서버만 확인하려면 `node seoul-proxy.mjs`를 실행합니다.
`http://localhost:8083/health`는 키 설정 여부만 반환하며, 키가 없으면 `/arrivals`는 503을 반환합니다.
앱은 API 오류를 표시하고 예상 시간 알림은 계속 제공합니다. 외부 호출에는 8초 제한이 있습니다.
`/positions?line=2호선`은 서울시 열차 위치 원본 응답 조회용이며 현재 화면의 알림 계산에는 사용하지 않습니다.
키는 서버 환경 변수에만 저장되며 앱 번들에 포함되지 않습니다.

휴대폰에서 접근하려면 `backend/.env`에 `HOST=0.0.0.0`을 설정하고 프런트엔드 API 주소의 localhost를 PC의 LAN IP로 바꿉니다.
다른 웹 주소/포트에서 실행할 때는 `FRONTEND_ORIGIN`을 해당 주소로 맞춥니다.
중계 서버는 로컬 개발용입니다. 배포 시 인증·호출량 제한·HTTPS 및 운영 서버 구성이 별도로 필요합니다.

## 검증

- `frontend`에서 `npm test`: 경로, API 변환/오류, 알림 중복/권한/취소/복원 회귀 테스트.
- `npm run typecheck`: TypeScript 검사.
- `npx expo export --platform web`: 웹 번들 빌드.
- 실기기: 권한 허용/거부, 백그라운드 예약, 취소, 앱 재시작 복원, OS 알림 확인.
